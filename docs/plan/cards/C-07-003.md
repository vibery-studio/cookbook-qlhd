# C-07-003 · SoD

## Goal
`GET/POST/DELETE /sod-pairs` chạy đúng §2b; không đường nào tạo được vai trò chứa cả hai mã của một cặp đã khai, kể cả khi đua.

## Context
SPEC-07 FR-1, FR-2, §3.3 "SoD", DEC-9 B, R-7. Khai cặp: `INSERT … SELECT … WHERE NOT EXISTS (vai trò có cả hai mã)` + audit có điều kiện, một batch; 0 dòng → liệt kê vai trò vi phạm → 409 `sod-conflict` `roles` (sắp theo `ROLE_ORDER` hệ thống rồi nhãn); UNIQUE → `duplicate`. Lưu `perm_a < perm_b` (sắp ở service). POST /roles: `sodViolations(perms, listSodPairs)` TRƯỚC `grant_not_held` (PLAN R-9) → 409 `pairs`; lặp `sodClearSql(perms)` trong WHERE của `insertCustomRoleStmt` (đua với khai cặp; 0 dòng → đọc lại phân loại `sod-conflict` trước `grant_not_held`/`role-limit`). D1 batch tuần tự ⇒ khai cặp ∥ tạo vai trò: một bên thắng. `sodClearSql` của 001: chỉ import. RUNWAY: route giữ `c`, DAO thuần, CAS + batch. **Không đổi OpenAPI.**

## Scope
In: file trong `touches`. Out: yêu cầu đổi quyền (004 — dùng `sodViolations`/`sodClearSql` cùng cách), web (007).

## Steps
1. `sod-dao.ts`: `insertPairStmt` (điều kiện), `deletePairStmt` RETURNING, `rolesHoldingBoth(db, a, b)`, `findPair`.
2. `sod-service.ts`: list (kèm `created_by_name`), add, remove; audit `sod.pair_added|removed {perm_a, perm_b}` target `sod:<id>` cùng batch.
3. `role-admin-service.createRole` + `role-write-dao.insertCustomRoleStmt` (thêm điều kiện SoD); route map `sod-conflict`.
4. `sod-pairs.routes.ts` handler thật.
