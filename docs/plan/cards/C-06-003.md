# C-06-003 · API vai trò

## Goal
`GET /roles` trả `{items, catalog}` đủ trường + `can`/`locked_reason` theo người gọi; `POST/PATCH/DELETE /roles` chạy đúng SPEC-06 §3.3 với mọi guard; người mang vai trò nhận quyền mới ở request kế tiếp.

## Context
SPEC-06 §3.3 (CAS + `db.batch`, stmt sau điều kiện `EXISTS(roles WHERE id=? AND version=?+1)`; 0 dòng → đọc lại phân loại 404/`stale`/403), §3.2 lỗi, FR-5 guard, FR-7, FR-8 (`role.created` · `role.updated` · `role.permissions_changed {added,removed}` · `role.deleted {name,label}`; target `role:<id>`), DEC-2 A (admin bất biến), DEC-4 B (TTL 60s). Quyền người gọi đọc **từ D1** (không principal cache). `grant_not_held`: `added ⊄ quyền actor` → 403 trước batch + lặp trong WHERE của INSERT. Mỗi 403 nghiệp vụ ghi 1 `permission.denied` (`metadata {rule, permission:"roles:write"}`), cùng kiểu FIX-03 `denyEscalation`. `name` vai trò mới = `"r_" + generateUlid().toLowerCase()`; ≤ 50 vai trò `is_system=0` → 409 `role-limit`. PLAN-06 R-5 (thứ tự `locked_reason`: admin > own_role > system; `admin_role` thắng `own_role`). RUNWAY: route giữ `c`, service không thấy `c`, DAO thuần, Problem+JSON. **Không đổi OpenAPI** (002 đã khóa); cần đổi → dừng, báo driver.

## Scope
In: file trong `touches`. Out: `/admin/users` (004), web (005/006), cắt lô >900 người (R-1, chỉ ghi doc).

## What was done
- `domain/role-label.ts` `normalizeLabel` (NFC → trim → collapse spaces → `toLocaleLowerCase('vi')`) + `role-label.test.ts` (spellings, 0017 literals).
- `role-dao.ts`: `listRoleDetails`/`findRoleDetail` (1 join query + 1 grouped holder count, system first), `listRoleIdsForUser`, `countCustomRoles`, `listUserIdsOfRole`; old `listRolesWithPermissions` removed (only GET used it). Actor permissions = existing `permission-dao.listPermissionKeysForUser` (read-only import, not edited).
- `role-write-dao.ts` (builders only): `insertCustomRoleStmt` (guard: < 50 custom AND actor holds all codes), `grantPermissionsStmt` (per-code `EXISTS` actor holds it), `revokePermissionsStmt`, `updateRoleCasStmt`, `deleteRoleCasStmt`, `deleteRolePermissionsStmt`, `editGuard`/`deleteGuard`, `auditWhenStmt` (own copy, not user-dao's).
- Plan deviation (SPEC §3.3 batch order): dependent stmts + audit go BEFORE the CAS write, guarded by `version = expected` (+ guards); CAS last. SPEC's "after, guarded by `version = expected+1`" is unsafe: a concurrent winner also makes `expected+1` true → loser's permission diff would apply. Batch = one transaction, so the "before" guard sees the same state as the CAS.
- `role-admin-service.ts`: list (`can`/`locked_reason` admin > own_role > system), create/patch/delete with guards `admin_role` → `system_role` (DELETE) → `own_role` → `grant_not_held`, then stale/`role-in-use`; caller roles+perms from D1; each 403 = 1 `permission.denied {rule, permission:"roles:write"}`; 0-row batch → re-read → 404/stale/403/`role-in-use`/`role-limit`; UNIQUE `label_key` → `duplicate`; after a permission change `Promise.all(invalidatePrincipalCache)` for every holder. Audit: `role.created {name,label,permissions}` · `role.updated {name,label,changed}` · `role.permissions_changed {name,label,added,removed}` · `role.deleted {name,label}`, target `role:<id>`.
- `roles.routes.ts`: real handlers, kind → Problem (403 `rule`/`permissions`, 404, 409 `stale`/`duplicate`/`role-limit`/`role-in-use`+`holders`); OpenAPI unchanged (`openapi:export && client:generate` → no client diff; 501 entries left in the spec as in 002).
- `session-cache.ts` TTL 300 → 60; `docs/auth.md` max-time-to-revoke (~60s); `docs/rbac.md` guards, `can` order, audit, cache purge by role + R-1.
- `test/integration/role-write-dao.test.ts`: control (held → 1 row, version 2) + actor loses code by SQL → grant 0 rows, CAS 0 rows, version 1.
