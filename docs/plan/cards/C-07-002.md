# C-07-002 · Hợp đồng OpenAPI trước mọi handler

## Goal
OpenAPI + client mô tả đúng PLAN-07 §2b; mọi route mới trả 501 sau đúng middleware (401/403 đã thật); cron mới được dispatch; test 2a dùng `PATCH permissions` đã chuyển sang luồng yêu cầu (đỏ tới 004).

## Context
PLAN-07 §2b nguyên văn (hình dạng, thứ tự lỗi, gate từng route). Gate thật ngay ở card này: `requireAuth` + `requirePerm` như §2b; route gate "service" (withdraw, revoke, items, `GET /access-reviews/current` any-of) → 501 sau `requireAuth` (403 thật ở 004/005/006). `GET /access-reviews/current`: middleware cục bộ "principal có `reviews:write` hoặc `roles:write`", thiếu → 403 + `permission.denied` (cùng mẫu `requirePerm` onDeny). `POST /admin/jit-grants`: `IdempotencyKeyHeader` + `withIdempotency()`. `RoleIdSchema` (2a) cho `{id}` vai trò; id mới (yêu cầu, cặp, grant, đợt) dùng `UlidSchema`; `{userId}` = `UlidSchema`. Problem + `pairs?: string[][]`, `roles?: {id,name,label}[]`; rule mới trong mô tả 403: `self_approve`, `jit_actor`, `self_grant`, `self_review`.
Cron (PLAN §3 điều phối): `crons/jit-expiry.ts` export `runJitExpiry(env: Bindings, nowSeconds: number)` → `sweepExpiredJit(deps, now)` (jit-service, stub trả 0); `crons/rbac-daily.ts` export `runRbacDaily(env, nowSeconds)` → `openQuarterReview(deps, now)` (access-review-service, stub) rồi `expireOverdueRequests(deps, now)` (role-change-service, stub) — mỗi nhánh try/catch + log `cron.rbac_daily.tick` (mẫu `pruneExpiredRows`). `index.ts` `scheduled`: `*/5` → `Promise.allSettled([verifyEmailSweeper(env), runJitExpiry(env, now)])`; `0 3` → `pruneExpiredRows` + `runRbacDaily`. Đây là bản cuối của 3 file cron/index — card sau không sửa.
`role-admin-service.toView`: thêm `can.request` (= `can.edit` tạm), `request_locked_reason: null`, `pending_request: null` (004 tính thật). `roles.routes.ts` PATCH handler thôi truyền `permissions`. `me.routes.ts`: schema + `jit: null` (005 tính thật).
R-1 — `roles-acceptance.test.ts` (chỉ 3 test, giữ ý đồ 2a; helper `requestChange`/`approve` viết cục bộ như file 2b):
- AC-2: PATCH bỏ `contract:issue` → GĐ `POST /roles/{ql}/change-requests` 201 + admin `approve` 200, `role.version` = before+1; giữ nguyên assert QL 403 lần kế, `/me`, 1 dòng `role.permissions_changed {added:[], removed:["contract:issue"]}`.
- AC-3: 2 PATCH song song đổi **nhãn** ("Quản lý A" bởi GĐ, "Quản lý B" bởi admin) → `[200, 409 stale]`, nhãn bên thắng, 1 dòng `role.updated`; phần stale tuần tự + 404 giữ.
- AC-5: `grant_not_held` của GĐ (thêm `settings:write` vào quan_ly) và admin (thêm `contract:approve` vào Kế toán) → qua `POST …/change-requests` (403, `permissions` như cũ); "bỏ mã mình không có" → yêu cầu `permissions: []` trên Kế toán → 201; "admin bỏ `users:write` khỏi giam_doc" → yêu cầu của admin + GĐ duyệt (bớt quyền, DEC-3) → GĐ mất `users:write`; `patchRole(admin, admin, {permissions})` → yêu cầu trên `admin` → 403 `admin_role`.
