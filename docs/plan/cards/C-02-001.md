# C-02-001 · Schema, append-only trigger, DTOs, OpenAPI 501 stubs, client

## Goal
After `pnpm db:migrate:local` the two tables exist and refuse UPDATE/DELETE on versions; `/docs` shows the four endpoints of SPEC-02 §3.8 (handlers return 501); the client is regenerated. First BUILD card: contract before any handler.

## Context
SPEC-02 §3.1 (columns), §3.8 (API), DEC-6 (trigger). Recipe `docs/recipes/add-resource.md`. Expand-only. Migrations are numbered at build time as "next" (row 03 follows). `template:write` already exists in `packages/rbac/src/catalog.ts` — do not touch the catalog. The `data-inventory` test forces the new tables into INVENTORY_EXEMPT_TABLES (business records, no personal data). Row-1 stub pattern: `routes/customers.routes.ts`.

## Scope
In: tables `templates` (`name_norm` UNIQUE, `current_version_id` plain TEXT, `active` default 1) and `template_versions` (UNIQUE(`template_id`,`version_no`), no `updated_*`); `pnpm db:generate` for DDL, then `pnpm db:generate --custom` for one hand-written migration with `BEFORE UPDATE` and `BEFORE DELETE` triggers on `template_versions` (`RAISE(ABORT, …)`); zod-openapi DTOs + `createRoute` for `GET /templates`, `GET /templates/{id}`, `POST /templates`, `POST /templates/{id}/versions` with guards (`requireAuth → requirePerm("contract:read" | "template:write") → withIdempotency` on POSTs) + 501; the request schema refuses shape errors as 422 `validation` (duplicate field keys, `choice` without `options`/`options_from`, unknown keys, bad `type`/`source` string shape, empty body); `ProblemType.TemplateCheckFailed = "template-check-failed"`; `ProblemDto.errors` items gain optional `code`, `key`, `source`; `dao/template-types.ts` (DTO types + row→DTO mappers, JSON columns parsed); `pnpm client:generate`. Out: any query, service, seed, check logic. No PATCH/PUT/DELETE routes.
