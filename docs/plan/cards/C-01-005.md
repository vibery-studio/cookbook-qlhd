# C-01-005 · Customers: create, edit (CAS), get, search, dedupe

## Goal
The team shares one customer list; duplicates by phone/tax code are refused with the existing id; concurrent edits never silently overwrite.

## Context
SPEC FR-5, DEC-4, §4 Input/Duplicates/Two people. Change + audit row in one `db.batch` (audit metadata: field names only). No DELETE.

## Scope
In: `normalizePhone` (+84/84→0, strip non-digits) · POST (409 `existing_id`) · PATCH `expected_version` CAS → 409 stale · GET one · list `q` over name (case/diacritic-insensitive where SQLite allows: LIKE on lower) + phone_norm + tax_code, cursor, ≤50. Out: import from xlsx.

## What was done

- `normalizePhone` (util + unit test), DAO, service, routes (list/get/create/patch) replace the 501 stubs. No DELETE.
- Create: customer insert + `customer.created` audit in one `db.batch`; race-safe via the partial UNIQUE indexes; on violation (batch rolled back) look up the holder → 409 `duplicate` + `existing_id`.
- Patch: `UPDATE … WHERE id AND version RETURNING` + audit `INSERT … SELECT … WHERE changes() > 0` in one batch (audit exists only if this update won; an EXISTS-version guard would leak a row when another edit already bumped the version). 0 rows → 404 (id unknown) else 409 `stale`. Audit `fields` = fields present in the request (not diffed, avoids a read).
- List: one query, keyset on (name, id), cursor = base64url JSON; `q` = name LIKE (ASCII case-insensitive; Vietnamese diacritics exact) OR phone_norm (when q is a valid phone) OR tax_code exact.
- Gaps (outside touches): dto/customers.ts regexes reject "" / padded tax_code and "" email before the service can null them.
