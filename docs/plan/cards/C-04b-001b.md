# C-04b-001b · API — rút về nháp

## Goal
`ContractCan` có `withdraw` + `delete`; `POST /contracts/{id}/withdraw` đưa hợp đồng `pending` chưa ai quyết về `draft`.

## Context
SPEC-04b §3.2 (C)(D)(F), FR-19, R-6, R-7. `can.withdraw = isCreator && pending && không step nào có decided_by`; `can.delete = isCreator && draft` (thêm cả hai ở đây để 001c không đụng lại `read-service.ts`). Route guard `contract:submit` + kiểm người tạo trong service (403 `forbidden` `rule=creator_only` + `permission.denied`, như submit/PATCH). Body `{}`, 200 → `Contract` (draft), không Idempotency-Key. Một `db.batch`: (1) CAS `UPDATE contracts SET status='draft', submitted_at=NULL, decided_at=NULL, version=version+1, updated_at=:now WHERE id AND status='pending' AND created_by=:actor AND NOT EXISTS (SELECT 1 FROM approval_steps s WHERE s.contract_id=:id AND s.status<>'waiting')` · (2) audit `contract.withdrawn` `{from:'pending',to:'draft'}` bằng `INSERT … SELECT … WHERE changes() > 0` (mẫu `customer-dao`) · (3) `DELETE FROM approval_steps WHERE contract_id AND status='waiting'` có điều kiện hợp đồng đã về draft. 0 dòng ở (1) → đọc lại phân loại: có step đã quyết → 409 `already-decided` (`current_status: "pending"`), khác → 409 `state-conflict`; không tồn tại → 404. Thêm slug `already-decided` vào `ProblemType`; hằng `contract.withdrawn` vào `CONTRACT_ACTIONS`. Một file service + một file DAO. R-7: nếu `changes()` không đúng thứ tự trong batch → dừng, báo driver. Không sửa `apps/api/test/integration/contracts-4b-acceptance.test.ts`, `contracts-acceptance.test.ts`. Ghi nhớ: route giữ `c`, service không thấy `c`, DAO thuần `(db, input) → DTO`, race bằng CAS + `db.batch`, lỗi Problem+JSON. Xong thì `pnpm openapi:export && pnpm client:generate` cùng commit. KHÔNG chạy vitest song song với agent khác; driver chạy suite đầy đủ.
