# C-06-002 · Hợp đồng OpenAPI trước mọi handler

## Goal
OpenAPI + client sinh ra mô tả đúng SPEC-06 §3.2 (GET/POST/PATCH/DELETE `/roles…`, `role: string` ở `/admin/users`, slug + trường Problem mới), để 003 ∥ 004 ∥ web làm theo một hợp đồng cố định.

## Context
SPEC-06 §3.2 nguyên văn. `Role = {id, name, label, description, is_system, version, holders, permissions[], can:{edit,delete}, locked_reason: null|"system"|"own_role"|"admin"}`; `RolesResponse = {items: Role[], catalog: string[]}`. `CreateRoleBody {label 1–60 (trim), description? ≤200, permissions: catalog[] không trùng}.strict()`, `PatchRoleBody {expected_version, label?, description?, permissions?}.strict()`, DELETE query `expected_version` int ≥1. POST có `IdempotencyKeyHeader` + `withIdempotency()`; mọi ghi `requirePerm("roles:write")`. Slug: `role-in-use`, `role-limit`, `unknown-role`; ProblemDto thêm `permissions?: string[]`, `holders?: number` (`rule` đã có). WORKFLOW: OpenAPI ở card đầu, trước handler. PLAN-06 R-2: `run_worker_first` thêm `"/roles/*"` cả 3 block env.

## Scope
In: DTO, định nghĩa route + middleware, handler POST/PATCH/DELETE trả 501 `not-implemented`; GET giữ handler cũ (thiếu trường mới = chấp nhận tới 003). `admin-users.routes.ts`: `role` thành `z.string().min(1).max(64)`, **chặn tạm** trong route: tên ngoài `giam_doc|quan_ly|nhan_vien|admin` → 422 `unknown-role` (để không có user mồ côi trước 004). Out: service/DAO (003/004), web.

## Steps
1. `dto/roles.ts` (mới) + chuyển `RoleItem/RolesResponse` khỏi `dto/users.ts`; `role: string` ở `InviteUserBody`/`UpdateUserBody`, bỏ `BusinessRole` nếu không còn ai dùng.
2. `dto/error.ts` slug + trường.
3. `roles.routes.ts`: 4 `createRoute` (responses 401/403/404/409/422 như SPEC), `app.on(...)` middleware, handler 501.
4. `admin-users.routes.ts`: response 422 `unknown-role` trong OpenAPI + chặn tạm.
5. `wrangler.toml` `"/roles/*"` × 3.
6. `pnpm openapi:export && pnpm client:generate`; `pnpm --filter @runway/web typecheck` vẫn xanh.
