# C-03-007 · Submit + decide

## Goal
Submitting creates the approval steps only if a distinct approver exists for every step; deciding is done by the right person on the current step,
never by the creator, never twice by one person, never in a way that strands a later step — each move one CAS + one audit row.

## Context
SPEC-03 FR-4, FR-5, §3.3 rows "gửi duyệt", "duyệt", "từ chối", I9 + SoD paragraphs, DEC-10. Workbook §9: SoD is a domain check, NOT
`requirePerm({ownerId})`; denials leave a trace. The policy used is the one pinned in the snapshot (`snapshot.policy`), vars = `{discount_bps, total}`.

## Scope
In: `approval-dao.ts`:
- `listCandidates(db)` → active users with role names + permission keys (one join; admin never has `contract:approve`).
- `submitCas(db, {id, actor, steps, now})` → batch: `UPDATE contracts SET status='pending', submitted_at WHERE id AND status='draft' AND created_by=:actor
  RETURNING` + INSERT steps `… SELECT … WHERE changes() > 0`-guarded (or conditional on the contract row) + audit {from, to, steps}.
- `decideCas(db, {id, actor, decision, note, now, isLast})` → batch: `UPDATE approval_steps SET status, decided_by, decided_at, note,
  snapshot_hash_at_decision = (SELECT snapshot_hash FROM contracts WHERE id) WHERE contract_id AND status='waiting' AND step_no = (SELECT MIN(step_no)
  … waiting) AND EXISTS(contract pending) AND NOT EXISTS (SELECT 1 FROM approval_steps WHERE contract_id AND decided_by=:actor)` then contract
  `pending→approved` (last step) / `pending→rejected` guarded by that step change, + audit guarded the same way.
- `getDecisionState(db, id)` → contract status/creator + steps (for the pre-checks and the 0-row diagnosis).
`submit-service.ts`: not found / not creator (403) / not draft (409) → `requiredSteps(snapshot.policy, vars)` → `eligibleAssignment(steps, candidates, {creator})`
→ fail: `no-eligible-approver{step}` (nothing written) → `submitCas`.
`decide-service.ts` order: not found → contract not pending (409 state-conflict) → current step → actor lacks step permission/role (403
`forbidden-permission` + `permission.denied` {permission}) → actor = creator (403 `sod` creator_cannot_approve + `permission.denied` {rule, target
`contract:<id>`, ip}) → actor decided another step (403 one_person_one_step + row) → approve only: DEC-10 `eligibleAssignment(remaining waiting
steps, candidates, {creator, deciders…, actor})` fails → 409 `would-block-later-step{step}` → `decideCas`; 0 rows → re-read: decided meanwhile →
409 `state-conflict` (or 403 one_person_one_step if the actor's own decision won elsewhere). Emit `contract.submitted/approved/rejected`.
Out: issue/void; routes; queue SQL (C-03-005).
