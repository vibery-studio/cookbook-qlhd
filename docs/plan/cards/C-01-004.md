# C-01-004 · Users: invite, activate, role/disable, last_admin, GET /roles

## Goal
Admin/Giám đốc add people by invite link; people activate and log in; role swap and disable bite on the next request; the last admin cannot lock the door.

## Context
SPEC FR-1..3, DEC-1/2, §4 Lifecycle. Exactly one role per user (swap = revoke all + grant one, one batch). `invalidatePrincipalCache` on every change; disable also revokes refresh chain. Token 32 bytes, hash only, 72h, single use (CAS `used_at IS NULL`).

## Scope
In: POST/PATCH `/admin/users`, `/invite`, `/auth/activate` (sets password, status active, verified), `GET /roles`, list `display_name`, email via EmailPort (best-effort), audit `user.invited|activated|role_changed|disabled`. Out: UI, password reset.

## Steps

## What was done
- user-admin-service.ts (new): inviteUser / reinviteUser / activateUser / updateUser. Invite = ONE db.batch (user pending + random-secret valid scrypt hash, one role, invite token 72h hash-only, audit user.invited). No invite email: EmailPort only has verify-email/password-reset templates (TODO: add `invite` template); admin shares activation_url.
- Activate: early read (skip scrypt for unknown token) then batch [CAS consume purpose='invite' RETURNING, activate user WHERE status='pending' RETURNING, conditional audit user.activated]; 0 rows -> 400 invalid-or-expired-token.
- Last-admin guard = SQL predicate `notLastActiveAdmin` inside the FIRST write of the batch (role INSERT..SELECT or users UPDATE); D1 batch is one serialized transaction, so no read-then-write window. Every later statement (drop old roles, status, refresh revoke, audit) is conditional on that write having landed -> refused change leaves no partial state and no audit row. Role swap = grant new, then drop others only if new is held.
- Disable: status + revoke all refresh tokens in batch; invalidatePrincipalCache after every applied change (middleware rejects disabled on cache miss). No jti insert: access jtis of the user are unknown (<=120s tokens; cache bust covers it).
- PATCH status on a pending user -> 409 conflict (use re-invite). GET /roles = one leftJoin query. GET /admin/users returns display_name. Seed script inserts the admin directly into local D1 (hashPassword from @runway/auth), `--name` supported, login proof kept.
- DAOs: unexecuted statement builders added (user-dao, role-dao, verification-token-dao); UserDto gained displayName; VerificationPurpose gained "invite".
