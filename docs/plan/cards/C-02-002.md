# C-02-002 · Pure template check

## Goal
One pure function that decides whether a template version may be stored, returning EVERY problem at once. Used by the seed test, `POST /templates` and `POST /templates/{id}/versions`. Buildable in parallel with the DB/route cards: no DB, no Hono, no I/O.

## Context
SPEC-02 FR-6 (a)–(g), §3.2 (body format), §3.3 (fields/sources/field_rules), §3.4 (`approval_policy`), Q-5 (limits: body 64 KB, 60 fields, 10 steps), §3.8 (`code` list). The source registry is ONE place (§3.6 "Mở rộng nguồn"): `subject:{name,contact_person,tax_code,phone,email,address}`, `price_list:{code,name,unit_price,duration_value,duration_unit}`, `derived:{doc_date,contract_end,total,total_in_words,discount_bps}`, `issue:number`, `manual`. Anything else (e.g. `deal:*`, `subject:zalo`) is unresolvable. Allowed permission/role names come from `@runway/rbac` (`isPermission`, `ROLE_NAMES` — read-only import; do not edit the package). No new dependency (hand-written tokenizer; CLAUDE.md: docs before install — none installed).

## Scope
In: `checkTemplate(input: {body: string; fields: FieldDef[]; field_rules?: FieldRule[]; approval_policy: unknown}): TemplateCheckError[]` — `[]` = OK; never throws; deterministic order; `TemplateCheckError = {code, key?, source?, message}` with `code` ∈ `placeholder_without_field · required_field_without_source · unresolvable_source · policy_invalid · internal_note · html_not_allowed · too_large · unbalanced_if · all_or_none_invalid`; Vietnamese messages naming the field. Exports `SOURCE_REGISTRY`, `isResolvableSource(s)`, `LIMITS`. Also: a malformed placeholder (`{{ Ten }}`, uppercase, spaces) is reported as `placeholder_without_field` with the raw text as `key`; `{{#if key}}` key must be a declared field. Duplicate field keys and `choice` without `options`/`options_from` are NOT this function's job: they are shape errors, refused by the Zod schema in C-02-001 (422 `validation`). `approval_policy`: modes `none|steps|threshold|combined`; `steps` required for steps/combined and non-empty; `rules` required for threshold/combined; `op` ∈ `gt gte lt lte eq`; `var` ∈ `discount_bps|total`; `permission` must be a real permission; `role` (optional) a real role; ≤ 10 steps counting `add_steps`. `all_or_none` keys must be declared fields. HTML: allowed tags `p h1 h2 h3 br strong em ul ol li table tr td th div span` (also `thead tbody` only if the seed needs them — it does not); only attribute `class` with values from a fixed list (`center right b sig`); fail-closed on comments, `<!`, unterminated `<`, `javascript:`, any `on*`, `style`, `href`/`src`; case-insensitive. Internal note: case-/diacritic-insensitive `ghi chú nội bộ`, `xóa trước khi gửi khách`. Size: body bytes via `TextEncoder`. Out: DB, HTTP, rendering/escaping values (row 3).

## Steps
1. `template-sources.ts` (registry + `LIMITS`). 2. `template-check.ts`: tokenise body once (placeholders, if/endif stack, tags) then run each rule, collect all errors. 3. Unit test file (below).

## Tests
`apps/api/test/domain/template-check.test.ts` (this card owns it; plain vitest, no miniflare needed) — one `it` per rule + the attack list: `<SCRIPT>`, `<p onClick=…>`, `<img src=x onerror=…>`, `<a href="javascript:…">`, `<style>`, HTML comment, uppercase tags, unterminated `<`; `{{ Ten }}`, `{{#if}}` unclosed / extra `{{/if}}` / nested / unknown key; unknown source (`deal:ten_khach`, `subject:zalo`); required + empty source; policy cases (unknown permission, `mode:"steps"` with `[]`, unknown `var`/`op`/`role`, 11 steps); 64 KB boundary in BYTES (64 KB ASCII passes, 65 KB fails; multi-byte Vietnamese counted by bytes); 61 fields; the seed policy passes; a full valid tiny template returns `[]`; many-errors input returns all of them in one call.
