# C-06-004 · API người dùng nhận mọi vai trò có thật

## Goal
`POST /admin/users` và `PATCH /admin/users/{id}` nhận `role` = tên vai trò có trong D1 (gồm `r_…`); tên không có, `member`, hoặc vừa bị xóa song song → 422 `unknown-role`, không bao giờ để lại user không vai trò. Người gọi không phải admin chỉ gán/gỡ được vai trò mà quyền của mình bao trọn (FR-12).

## Context
SPEC-06 §3.3 "Mời/đổi vai trò": stmt đầu `INSERT…SELECT FROM roles WHERE name=?` phải trả 1 dòng; mời: `insertInvitedUserStmt` điều kiện `EXISTS(roles WHERE name=?)` (hoặc chèn user sau grant) → batch tuần tự, vai trò bị xóa giữa chừng → 0 dòng → 422. FIX-03 đã thêm `self_role`/`admin_only` vào cùng file — giữ nguyên, chỉ thay phần "vai trò hợp lệ". Bỏ **chặn tạm** 4 tên ở route (C-06-002).
FR-12 (SPEC-06 §0): `missing = (perms(vai trò mới) ∪ perms(vai trò cũ của người đó)) − perms(actor)`, đọc từ D1 trong cùng request (không principal cache); actor mang `admin` được miễn; `missing ≠ ∅` → 403 `forbidden` `rule:"grant_not_held"` + `permissions: missing` (sắp xếp) + 1 dòng `permission.denied` (`target user:<id>` / `user:new`, `metadata {rule, permission:"users:write", role}` — cùng kiểu `denyEscalation` của FIX-03). Thứ tự kiểm: `self_role`/`admin_only` (FIX-03) → `unknown-role` (gồm `member`) → `grant_not_held`. Đua (actor bị gỡ quyền giữa chừng): kiểm trước batch là đủ theo SPEC ("kiểm từ D1 trong cùng request"); muốn đóng hẳn thì lặp điều kiện trong WHERE của grant như C-06-003 — ghi quyết định vào "What was done". PLAN R-12: test cũ có thể đổi kỳ vọng. `grantRoleByNameStmt` (role-dao) dùng nguyên, không sửa `role-dao.ts` (003 sở hữu). **Không đổi OpenAPI.**

## Scope
In: file trong `touches`. Out: ẩn `member`/`admin` ở UI (006), guard DEC-5 (FIX-03, đã xong), `role-dao.ts` (003 sở hữu — đọc quyền theo tên vai trò viết ở `permission-dao.ts`).

## Steps
1. `user-dao.ts`: `insertInvitedUserStmt` nhận `when?: SQL` (giống `grantRoleByNameStmt`).
2. `user-admin-service.ts`: kind mới `unknown-role` (mời + đổi vai trò); phân loại khi grant trả 0 dòng (vai trò không có vs `last-admin`).
3. `permission-dao.ts`: `listPermissionKeysForRoleNames(db, names)`; quyền actor dùng `listPermissionKeysForUser` có sẵn.
4. Service: kind `grant-not-held {missing}` cho mời + đổi vai trò, ghi denied.
5. `admin-users.routes.ts`: bỏ chặn tạm, map `unknown-role` → 422, `grant-not-held` → 403 có `rule` + `permissions`.
