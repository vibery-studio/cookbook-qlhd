# C-02-005 · Write side

## Goal
Only `template:write` (Giám đốc) can create a template or add the next version; a bad version is refused whole with the complete error list; two racing writers give one 201 + one 409 `stale`; every success has exactly one audit row in the same batch.

## Context
SPEC-02 §3.8 (order: Zod → permission → `template-check-failed` → CAS/write), FR-1/5/6/7, §4 (duplicate name via `name_norm` UNIQUE → 409 `duplicate` + `existing_id`; Two people at once; Idempotency-Key). CAS in `db.batch`, never check-then-write (CLAUDE.md). Audit via `auditInsert` (unexecuted) in the SAME batch: `template.created` / `template.version_created`, target `template:<id>`, metadata `{version_no, fields: <count>}` — never the body. Reuse `isUniqueViolation`. DAO has NO update/delete function. Response = `getTemplateDetail` (C-02-004).

## Scope
In: `template-write-dao.ts` (`insertTemplateWithV1`, `insertNextVersionCas`): version INSERT guarded by "current version_no = expected", `templates.current_version_id` moved by `UPDATE … WHERE current_version_id = <expected id>`, audit row conditional on the version row landing; UNIQUE(`template_id`,`version_no`) violation → `stale`. `template-write-service.ts`: normalise (`name_norm` = trim + lowercase), call `checkTemplate` (C-02-002), map results to tagged outcomes (`ok | not_found | stale | duplicate | check_failed`). Handlers in `templates-write.routes.ts`: 201 detail; 409 `stale` / `duplicate` (with `existing_id`); 422 `template-check-failed` with `errors[]` = `{path, code, key?, source?, message}`, content-type `application/problem+json`; 404 unknown template. Out: PATCH/PUT/DELETE, deactivate (DEC-3), seed, DTO/schema changes (if the contract must change, stop and ask the driver — shared files).

## Steps
1. write DAO. 2. service (check before write; nothing written on `check_failed`). 3. handlers. 4. run the concurrency + idempotency acceptance tests several times.
