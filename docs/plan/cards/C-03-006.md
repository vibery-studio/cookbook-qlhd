# C-03-006 · Create / edit draft / copy

## Goal
A draft is born only with every required field, server-computed prices/dates/words and a hashed snapshot pinned to a template version;
the creator can edit it (CAS on `version`); a rejected/voided contract can be copied into a fresh draft priced today.

## Context
SPEC-03 FR-1, FR-2, FR-3, FR-7, DEC-4 (doc_date = today VN at create and each edit; `ngay_bat_dau` follows unless entered by hand), DEC-7 (copy uses
today + current template), §3.3 rows "tạo", "sửa nháp", "chép sang nháp". Audit metadata = field NAMES only. Snapshot ≤ 256 KB → 422.

## Scope
In: `snapshot-builder.ts` `loadAndBuild(db, {templateVersionId | templateId, customerId, values, now, manualStart})`: row 02
`getTemplateVersionById`/`getCurrentVersion` → `getCustomer` → `priceListAt(db, docDate)` pick `ma_goi` → domain `buildSnapshot` → `snapshotHash`.
`contract-write-dao.ts`: `insertContract(db, row, audit)` (INSERT + `auditInsert` in one batch; `customer_name`/`total` copied from snapshot);
`updateDraftCas(db, {id, expectedVersion, actor, patch, fieldNames})` → `UPDATE … WHERE id AND status='draft' AND version=:v AND created_by=:actor
RETURNING` + audit via `INSERT … SELECT … WHERE changes() > 0` (row-1 `updateCustomerCas` pattern); `insertCopy(db, {row, sourceId, sourceVoided})`
→ batch: INSERT new draft (`source_contract_id`) + (voided) `UPDATE source SET replaced_by_id=:new WHERE id AND status='voided' AND replaced_by_id IS NULL`
+ audit; if that UPDATE touched 0 rows the batch must fail (guard with a CHECK-failing statement or a conditional INSERT, e.g. `INSERT … SELECT …
WHERE changes() = 1` placed so the new row is rolled back) → 409. On 0 rows elsewhere: re-read → `not-found` | `forbidden` | `state-conflict` | `stale`.
Services emit `contract.created` / (none for update) via `emitContractEvent` after the batch commits.
Out: submit/decide/issue; routes.

## Steps
1. builder. 2. create. 3. update (manual start detection: `values.ngay_bat_dau` present → manual; else follow doc_date). 4. copy. 5. events.

## What was done

Đã triển khai đủ luồng tạo nháp, sửa nháp theo CAS và chép từ hợp đồng bị từ chối/hủy:

- `snapshot-builder.ts`: ghim phiên bản mẫu, đọc khách hàng + giá theo ngày VN, gọi domain snapshot/hash và chặn snapshot quá 256 KB.
- `contract-write-dao.ts`: INSERT/CAS update cùng audit trong `db.batch`; copy hợp đồng hủy dùng guard CHECK để rollback khi CAS thay thế thất bại.
- Ba service: tính lại snapshot khi tạo/sửa/chép, giữ template đã ghim trừ khi chọn bản hiện hành, phát `contract.created` sau commit.
